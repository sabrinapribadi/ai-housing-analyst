# ADR-002: A Tool-Using Agent, Not Free Text or Generated Code

**Status:** Accepted — written retrospectively on 2026-11-11 from the code and PRD; the decision dates from June 2026
**Date:** 2026-11-11
**Deciders:** Sabrina Pribadi

---

## Context and Problem Statement

- Users ask questions in plain English; language models invent numbers when asked directly.
- **Question:** how should the assistant answer data questions so that numbers come from the data?

## Decision Drivers

- Every number must be computed by code, not written by the model.
- Low cost per question; works with one API key.

## Decision

- A LangChain/LangGraph agent on `gpt-4o-mini` (temperature 0) with **7 tools** over the listings: summary statistics, review statistics, price distribution, price by neighbourhood, price by room type, cluster summary and neighbourhood recommendation (`src/agent/agent.py`).
- Tools compute numbers and charts with pandas; the model chooses tools and writes the sentence around their results.

## Considered Options (SOTA comparison: tested here vs cited only, R2)

| Option | Tested here | Why |
|---|---|---|
| **Tool-using agent (reason-and-act pattern)** | **Yes (chosen)** | Numbers come from tools; the model only routes and phrases |
| Model writes pandas or SQL code | No | Generated code can be wrong and is harder to check |
| Plain chat over a data summary | No | The model would state numbers it was not given |

## Consequences

- **Positive:** answers cite computed numbers; new questions need a new tool, not new prompts.
- **Negative:** questions outside the 7 tools get weaker answers; cost and latency per question are not measured (R13 gap).
