# ADR-005: Analytics Methods — Sentiment, Clusters and Forecast

**Status:** Accepted for sentiment and clusters; forecast on hold (no prices in the calendar). Written retrospectively on 2026-11-11 from the code and PRD; the decisions date from June 2026
**Date:** 2026-11-11
**Deciders:** Sabrina Pribadi

---

## Context and Problem Statement

- The dashboard needs guest sentiment by area, natural groups of listings, and a price outlook.
- **Question:** which simple, explainable methods answer these on a laptop?

## Decision

- **Sentiment:** TextBlob polarity per review; positive above 0.1, negative below −0.1; a note warns about translated and mixed-sentiment reviews.
- **Clusters:** K-Means on latitude, longitude and price (standardised); k fixed at 5 in the app and agent; an elbow search up to 10 exists in `src/analytics/clustering.py` but is not called.
- **Forecast (on hold):** Prophet on the daily average calendar price (`src/models/forecast.py`). The September 2025 calendar has no prices (0 of 10,199,937 rows), so no forecast is trained and the app does not show one.

## Considered Options (SOTA comparison: tested here vs cited only, R2)

| Method | Tested here | Why |
|---|---|---|
| **TextBlob polarity** | **Yes (chosen)** | Simple, no API cost |
| VADER rule-based sentiment | No (cited) | Built for social-media English; reviews are multilingual |
| Transformer sentiment models | No | Better on nuance; heavier to run |
| **K-Means on location and price** | **Yes (chosen)** | Clear, map-friendly groups |
| Prophet | Not run: no calendar prices | Seasonality with little tuning; code kept for a snapshot with prices |

## Consequences

- **Positive:** fast, explainable, free.
- **Negative:** sentiment and clusters are not validated against labels; no price forecast is possible from this snapshot; a later snapshot with calendar prices would need a held-out test.
